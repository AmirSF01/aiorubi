# Bilingual documentation (EN / FA)

The docs build in two languages: English (source) and Persian (fa). The tooling
mirrors [aiogram](https://github.com/aiogram/aiogram): Sphinx `furo` + gettext
catalogs driven by `sphinx-build -b gettext` and `sphinx-intl`, no bespoke build
scripts.

## Layout

- `docs/*.rst` — English sources (single source of truth)
- `docs/locales/pot/` — gettext templates, committed for reference
- `docs/locales/fa/LC_MESSAGES/*.po` — Persian translation of every page
- `docs/locales/fa/LC_MESSAGES/**/*.mo` — compiled from `.po`, gitignored
- `docs/_static/bilingual.css` — RTL layout + Vazirmatn for the fa build
- `docs/_static/language_switcher.js` — EN/FA switcher in the header
- `docs/_templates/base.html` — sets `dir="rtl"` on `<html>` for the fa build

`docs/conf.py` reads `READTHEDOCS_LANGUAGE` and defaults to `en`; a Persian
translation project on Read the Docs builds in `fa` automatically, and locally
the `-D language=fa` flag does the same.

## Rebuild workflow

From the repo root the entry points are `make` targets in `docs/Makefile` (and
`docs/make.bat` on Windows). On machines with `uv` the root `Makefile` wires them
up (`make docs-gettext`, `make docs-serve`, `make docs-serve-fa`).

```bash
cd docs

# translate: regenerate templates and merge new strings into fa .po
make update-intl                 # = sphinx-build -b gettext + sphinx-intl update

# compile the gitignored .mo from the .po files (pure Python, needs no msgfmt)
make mo                          # = sphinx-intl -c conf.py build -l fa

# build both languages
make bilingual                   # -> _build/html/en and _build/html/fa

# ...or a single language by hand:
make html                        # English (sphinx-build -M html)
make -e language=fa html         # Persian only
```

On Windows without GNU make, use the equivalent batch verbs — `make.bat update-intl`,
`make.bat mo`, `make.bat bilingual` — with the docs extra on `PATH`
(`.venv-docs\Scripts`) or under `uv run --extra docs`.

Sphinx loads `.mo` (compiled) catalogs, not `.po`. `sphinx-intl build` writes them
with Babel, so no GNU gettext binaries are required on any platform; `.mo` files
are gitignored and the Read the Docs build regenerates them in its `pre_build` job.

## Read the Docs

One config in `.readthedocs.yml` serves both projects. English is the default
build; link a Persian translation project (language `fa`) against the same branch.
`post_install` installs `.[docs,redis,mongo]` and `pre_build` runs
`sphinx-intl -c docs/conf.py build -l fa`. Set the language per project in the
Read the Docs admin — do not hard-code it in `conf.py`.

## Validation

```bash
cd docs
sphinx-intl stat -l fa                                   # translated vs untranslated
grep -rc '^msgstr ""' locales/fa/LC_MESSAGES --include="*.po" | grep -v ':0'
```

## Conventions for translators

- Code identifiers (class/method/param names) stay in Latin script inside ``...``.
- Common loanwords: بات، هندلر، آپدیت، فیلتر، میان‌افزار، روتِر، توکن، وب‌هوک.
- Use نیم‌فاصله (ZWNJ): می‌شود، نکنید، به‌عنوان.
