# Bilingual documentation (EN / FA)

The docs build in two languages: English (source) and Persian (fa).

## Layout

- `docs/` — English RST sources (single source of truth)
- `docs/locales/pot/` — gettext templates (`sphinx-build -b gettext`)
- `docs/locales/fa/LC_MESSAGES/*.po` — Persian translations of every page
- `docs/_static/bilingual.css` — RTL layout + Vazirmatn font for the fa build
- `docs/_static/language_switcher.js` — EN/FA switcher in the header
- `docs/_templates/layout.html` — sets `dir="rtl"` on `<html>` for fa

## Rebuild workflow

```bash
# 1. Regenerate translation templates after editing sources:
cd docs
sphinx-build -b gettext . locales/pot

# 2. Merge new strings into the fa .po files (keeps existing translations):
sphinx-intl update -p locales/pot -l fa

# 3. Translate new/changed msgstr entries (e.g. with your editor / Weblate).

# 4. Build both languages:
rm -rf _build/html/en _build/html/fa
sphinx-build -b html . _build/html/en                       # English
sphinx-build -b html -D language=fa . _build/html/fa        # Persian (RTL)

# 5. Serve /en/ and /fa/ side by side (the switcher expects this layout).
```

The language switcher maps `/en/<page>.html` ↔ `/fa/<page>.html`, so both
builds should be published under a language prefix (GitHub Pages: `en/` and
`fa/` directories, or Read the Docs multi-language config).

## Validation

```bash
# every msgstr filled:
grep -rc '^msgstr ""' locales/fa/LC_MESSAGES --include="*.po" | grep -v ':0' 

# po syntax + markup balance:
msgfmt --check locales/fa/LC_MESSAGES/index.po
```

## Conventions for translators

- Code identifiers (class/method/param names) stay in Latin script inside ``...``.
- Common loanwords: بات، هندلر، آپدیت، فیلتر، میان‌افزار، روتِر، توکن، وب‌هوک.
- Use نیم‌فاصله (ZWNJ): می‌شود، نکنید، به‌عنوان.
